# Melanoma Detection App

A web application for detecting melanoma from skin lesion images using Gemini Vision AI.

## Features

- **Image Upload / Webcam**: Upload or capture skin lesion images directly in the browser
- **AI Analysis**: Powered by Google Gemini Vision — ABCDE criteria-based melanoma screening
- **Scan History**: Review all past analyses in one place
- **UV Index**: Real-time UV risk based on your location (Open-Meteo API)
- **Email Reminders**: Monthly skin-check reminders via Gmail SMTP

## Deploy on Render (Recommended)

### 1. Push to GitHub
Make sure the project is pushed to your GitHub repository.

### 2. Create a New Web Service on Render
- Go to [render.com](https://render.com) → **New → Web Service**
- Connect your GitHub repo
- Render will auto-detect the `render.yaml` Blueprint — click **Apply**

### 3. Set Environment Variables in the Render Dashboard
After the service is created, go to **Environment** and add:

| Variable | Description |
|---|---|
| `GEMINI_API_KEY` | Google AI Studio API key |
| `EMAIL_USER` | Gmail address for sending reminders |
| `EMAIL_PASS` | Gmail App Password (not your account password) |
| `APP_URL` | Your Render URL e.g. `https://melanoma-detect.onrender.com` |
| `SESSION_SECRET` | Auto-generated by Render (via `render.yaml`) |
| `RESEND_API_KEY` | *(Optional)* Resend email API key |
| `BREVO_API_KEY` | *(Optional)* Brevo email API key |

> **Gmail App Password**: Go to your Google Account → Security → 2-Step Verification → App passwords. Generate one for "Mail".

### 4. Deploy
Render will run `npm ci && npm run build` then `npm run start` automatically. Your app will be live at `https://<service-name>.onrender.com`.

## Troubleshooting

- **`npm` not recognized**: Ensure Node.js is installed and on your PATH
- **Gemini analysis fails**: Check `GEMINI_API_KEY` is set and the key has quota remaining
- **Emails not sending**: Verify `EMAIL_USER` / `EMAIL_PASS` are set; use a Gmail App Password, not your account password
- **Session resets on restart**: Set a strong `SESSION_SECRET` — the default fallback is for development only
